# Synthesis criteria

Read all three reviews and the underlying evidence. Inspect each proposed target skill. Check:

- **Durability:** the lesson survives routine version and file changes.
- **Specificity:** a future agent can recognize when it applies and what to do differently.
- **Causality:** evidence connects the proposed instruction to the observed failure; do not infer that more prose would have prevented it.
- **Ownership:** the existing skill actually owned the work, or a visible applicable skill missed selection. New skills require a recurring unmet need.
- **Existing coverage:** reject duplicate advice. If placement or ambiguity caused the issue, propose a precise correction to that instruction rather than another copy.
- **Enforcement:** mechanical prevention belongs in a structural backlog when it is more reliable than prose. If already enforced, identify the real gap before proposing another mechanism.
- **Independent support:** convergent findings deserve inspection, but agreement is not proof. A well-supported singleton may be accepted; unsupported consensus may not.

Return three groups:

**Accepted:** each row names the failure, evidence, exact proposed edit, canonical path and section, expected decision change, and validation scenario. These are proposals, not approval to write.

**Rejected:** each candidate has a concrete reason, such as insufficient evidence, transient detail, already covered, wrong owner, duplicate, or no demonstrated effect.

**Backlog:** each item describes a structural mechanism or unresolved investigation, its evidence, intended benefit, and scope. Filing or implementing it requires the user's authorization.

Merge duplicates without dropping conflicting evidence. Keep open questions open. Spot-check citations with authorized reads; do not invent source paths, successful checks, or facts missing from the transcript. Return recommendations without editing or publishing anything.
